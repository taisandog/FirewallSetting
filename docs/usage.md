## 一、核心工作流程概览

系统通过安全签名保证动态 IP 能够合法、安全地写入防火墙白名单，典型使用步骤如下：

```text
+-----------------------+                    +------------------------+
| 1. 服务端创建用户      |                    | 2. 客户端导入配置      |
| 生成用户配置 JSON 串   | -----------------> | 粘贴配置并保存         |
+-----------------------+  (复制配置码)       +------------------------+
                                                          |
                                                          | 3. 定时或手动发起同步
                                                          v
+-----------------------+                    +------------------------+
| 5. 服务端放行 IP      | <----------------- | 4. 发送动态签名请求    |
| 更新底层防火墙白名单   |   (验证通过放行)   | 包含当前公网 IP 与时间戳|
+-----------------------+                    +------------------------+
```

## 二、服务端使用与管理

### 1. Linux 服务端控制台管理 (CLI)

`FirewallSettingServerCore` 提供了内置的交互式管理控制台。

#### 如何进入控制台：
- **前台运行模式**：直接执行 `sudo dotnet FirewallSettingServerCore.dll`，程序就绪后会输出系统信息并显示 `命令:` 提示符。
- **Supervisord 模式**：通过命令 `sudo supervisorctl fg firewallsetting` 附着到前台交互。
- **Systemd 模式**：如需新增用户，可先停止服务 `sudo systemctl stop firewallsetting`，前台执行命令完成添加后输入 `exit` 退出，再重新启动服务 `sudo systemctl start firewallsetting`。

#### 命令列表与使用示例：

| 命令格式 | 参数说明 | 功能说明 |
| :--- | :--- | :--- |
| `user add <用户名> [isMultiple]` | `用户名`：用户账号标识<br>`isMultiple`：`1` 为多IP，`0` 为单IP（默认0） | 新增授权用户，并打印生成的客户端配置 JSON |
| `user show <用户名>` | `用户名`：已有用户名称 | 查询并显示指定用户的客户端配置 JSON |
| `user renew <用户名> [isMultiple]` | `用户名`：已有用户名称<br>`isMultiple`：是否允许多IP | 重新生成该用户的安全密钥（立即作废旧密钥） |
| `refreash` | 无参数 | 立即重新扫描并刷新当前底层防火墙与 IPSet 白名单 |
| `clear` | 无参数 | 清空当前终端控制台屏幕 |
| `exit` | 无参数 | 正常关闭程序退出（在 Systemd/Supervisor 守护下进程会被守护重启） |

#### 详细命令演练：

1. **新增单 IP 用户（默认覆盖模式）**
   ```text
   命令:
   user add zhangsan
   ```
   输出：
   ```json
   用户配置:{"Name":"生产服务器-Linux","Url":"http://120.79.xx.xx:8789","UserName":"zhangsan","Secret":"bd7b37013ac16d4280177cac0dc6d4a4|44eb607c8a3f7745a89ce5e40085dd2d|853605f579b1674f9f0921f01238f417","V2":"1"}
   ```
   > 复制这整段 JSON 内容，发给该用户即可。

2. **新增多 IP 用户（支持同时在家和办公室连接）**
   ```text
   命令:
   user add lisi 1
   ```
   > 参数末尾加上 `1`，表示该用户允许多个 IP 同时有效。系统会自动维护该用户的 IP 列表，并在客户端超过 60 分钟未更新某 IP 时自动将其清理。

3. **重新生成密钥（用户电脑中毒或密钥泄露）**
   ```text
   命令:
   user renew zhangsan 1
   ```

### 2. Windows 服务端图形界面管理 (GUI)

Windows 服务端 `FirewallSetting.exe` 采用全图形化界面操作，清晰直观。

#### 用户列表右键菜单操作：
在主界面的上方用户列表空白处或用户条目上 **单击鼠标右键**，可弹出管理菜单：
- **新增用户**：弹出对话框，输入用户名后自动随机生成强密钥并创建用户。
- **重置密码**：选中某一用户后点击，将立刻为该用户重新生成全新的安全码（旧配置码即刻失效）。
- **复制此用户配置**：一键将该用户的客户端配置 JSON 字符串复制到 Windows 剪贴板，方便通过聊天工具直接发送给用户。
- **删除**：从授权列表中彻底移除该用户并清空其对应的防火墙白名单。
- **配置文件(userInfo.xml)**：快速打开本地存储的用户凭据 XML 文件进行查看或备份。
- **重新应用到防火墙**：强制重新扫描 Windows 高级安全防火墙，并将当前所有有效用户的白名单重新写入规则的“作用域 -> 远程 IP 地址”。

#### 服务启动与开机运行：
- **服务启动**：点击界面右上角的“启动监听”或在加载配置后自动监听。
- **开机自动运行**：勾选界面底部的 **开机自动运行** 复选框，程序会写入系统自启注册表，每次开机后自动隐蔽在右下角托盘默默守护。

## 三、客户端使用指南

### 1. Windows 桌面客户端 (FWSettingClient)

`FWSettingClient.exe` 是专为 Windows 终端用户打造的轻量级后台客户端，无需安装，解压即用。

#### 首次使用步骤：
1. **运行程序**：
   双击运行 `FWSettingClient.exe`。
2. **托盘图标**：
   程序运行后会在 Windows 右下角任务栏托盘区域生成一个小图标。双击托盘图标，即可打开客户端主界面。
3. **添加服务器配置**：
   - 在已加载服务列表空白处 **单击鼠标右键**，选择 **添加**（或点击界面下方的添加按钮）；
   - 在弹出的输入框中，直接粘贴从管理员处获取到的完整 JSON 配置码；
   - 点击确定，主列表中即会出现该服务器条目，并立即执行首次 IP 白名单同步。
4. **验证状态**：
   界面下方的消息日志栏会提示：
   `[服务器名]: yyyy-MM-dd HH:mm:ss 进行了IP同步`
   表示您的当前外网 IP 已经成功加白，可以正常连接服务器端口（如远程桌面 RDP 3389、数据库等）。

#### 日常功能与特性：
- **后台全自动同步**：
  客户端内置后台线程，每隔 **5 分钟** 自动发起一次网络同步。即便宽带路由器自动换 IP，也能在几分钟内无感知恢复。
- **手动立即同步**：
  如果您重启了路由器或切换了网络（例如由 WiFi 切换到手机热点），无需等待 5 分钟，直接在客户端主界面点击 **同步IP到服务器**（或托盘右键手动同步），几秒钟内即可刷新。
- **管理多台服务器**：
  支持导入多台不同的服务器配置（如公司的研发机、测试机、生产机），客户端会在后台同时对所有配置的服务器并发更新白名单。
- **开机自动启动**：
  勾选主界面上的 **开机启动** 复选框。以后每次开机登录 Windows，客户端都会自动启动并直接最小化到托盘，无需手动点开。
- **关闭按钮逻辑**：
  点击右上角的关闭按钮 `X` 并不会退出程序，而是自动隐藏至托盘后台继续工作。若要彻底退出，请右击托盘图标选择“退出”。

### 2. 服务端内置 Web 客户端（开箱即用）

适用于 Mac、Linux 桌面端、手机平板，或者不想在本地 Windows 电脑上运行常驻后台客户端的用户。

> [!TIP]
> **免安装免配置**：
> 早期代码库中的 `FWSettingWebClient` 独立工程已被废弃。目前 Web 客户端已经**直接内嵌在服务端（无论是 Linux 服务端还是 Windows 服务端）**，开箱即用，无需配置额外端口或独立部署！

#### 访问入口：
直接在浏览器中打开：
`http://<服务器IP>:<服务端监听端口>/web/index.html`  
*(例如：`http://120.79.xx.xx:8789/web/index.html` 或 `http://192.168.31.28:8789/web/index.html`)*

#### 界面操作指引：
1. **添加服务配置**：
   - 打开网页，在页面中部的 **配置码** 文本框内，粘贴服务端提供的配置 JSON。
   - 点击 **添加服务** 按钮。上方服务器列表会自动刷新并新增一条服务器记录。
2. **多服务器列表管理**：
   - 服务器表格中会列出所有已添加的服务器名称；
   - 点击某一服务器右侧的 **删除** 链接，可将其从当前浏览器中移除。
3. **自动同步与手动同步**：
   - **自动同步**：只要浏览器标签页处于打开状态，页面每隔 **60 秒** 会自动检查并向后端上报最新的公网 IP。
   - **手动同步**：点击 **手动同步** 按钮，会立即触发向列表内所有服务器的 IP 上报。
4. **日志查看**：
   - 下方“消息”控制台会实时展示上报响应日志，如 `生产服务器-Linux, 更新IP完毕`。
5. **数据存储机制**：
   - Web 客户端的数据保存在浏览器的本地存储（`localStorage`）中，关闭网页下次打开配置依旧存在。
   - 如清理了浏览器缓存或更换了浏览器/电脑，只需重新粘贴配置码添加一次即可。

## 四、配置 JSON 结构解析

无论通过命令行还是图形界面生成的用户配置，其标准 JSON 结构如下：

```json
{
  "Name": "生产服务器-Linux",
  "Url": "http://120.79.xx.xx:8789",
  "UserName": "zhangsan",
  "Secret": "bd7b37013ac16d4280177cac0dc6d4a4|44eb607c8a3f7745a89ce5e40085dd2d|853605f579b1674f9f0921f01238f417",
  "V2": "1"
}
```

### 字段说明：
- `Name`：服务器备注名称，导入客户端后作为条目标题展示。
- `Url`：服务端提供 API 校验的公网地址及端口。
- `UserName`：为该客户端分配的独立用户名。
- `Secret`：服务端生成的专属多段 GUID 安全密钥，客户端用于生成 SHA-1 哈希签名，**严禁泄露给非授权人员**。
- `V2`：验证协议版本号（`1` 表示使用防篡改安全性更高的 V2 校验机制）。

## 五、日常运维场景与常见问题

### 1. 办公网络或家庭宽带掉线重启后连不上服务器？
- **原因**：宽带重拨后 ISP 分配了新的动态 IP，而客户端每 5 分钟同步一次，中间可能存在最多 5 分钟的时间窗口。
- **解决**：打开客户端主界面，点击 **同步IP到服务器**（或 Web 版点击“手动同步”），几秒钟内即可刷新防火墙，恢复连接。

### 2. 为什么提示“效验错误，错误次数：X”或“IP被屏蔽”？
- **原因**：客户端配置中的 `Secret` 或 `UserName` 与服务端记录不一致。服务端为了防范暴力破解，当同一 IP 在 5 分钟内错误达到 5 次时，会将该 IP 临时拉黑 5 分钟（`BlockSecond = 300` 秒）。
- **解决**：核对配置码是否粘贴完整；若已被拉黑，请暂停同步，等待 5 分钟后解封，或由管理员在服务端重新生成配置码。

### 3. 多台设备（笔记本 + 台式机）使用同一个用户名是否可以？
- 如果服务端添加用户时未开启多 IP（即 `isMultiple=0`），后上报的设备 IP 会**覆盖**先上报的设备 IP，导致另一台设备连接中断。
- **解决**：建议为每位员工或每台独立电脑在服务端分配不同的用户名；或者在创建该用户时指定多 IP 模式（CLI: `user add 用户名 1`）。

### 4. 服务端迁移或公网 IP 变更后怎么处理？
- 如果服务器的外网 IP 发生了变动，管理员修改服务端 `App.config` 中的 `Server.URL`，然后在服务端重新复制用户配置，客户端删除旧服务条目并重新添加新配置即可。
